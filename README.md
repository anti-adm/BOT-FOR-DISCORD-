# Рядом — веб-панель войса

Отдельная панель прослушивания существующего аудиобуфера Discord-бота. Код бота не изменяется, токен Discord не используется. Требуется согласие участников на прослушивание.

## Размещение

- GitHub Pages: содержимое `public/` в корне ветки `gh-pages`, Pages → Deploy from branch → gh-pages.
- Vercel: импортировать этот репозиторий, Output Directory `public`, без сборки. Добавить точный HTTPS origin сайта в `ALLOWED_ORIGINS` на VPS и перезапустить только `afk-listen`.
- VPS: отдельный процесс Node.js, `deploy/afk-listen.service`, Caddy для HTTPS. Backend слушает только `127.0.0.1:8787`. Порты снаружи — 80/443.

Переменные отдельного файла `/etc/afk-listen.env`:

```
LISTEN_KEY=<случайный ключ минимум 32 символа>
AUDIO_DIRECTORY=/opt/afk-bot/data/audio-buffer
ALLOWED_ORIGINS=https://anti-adm.github.io,https://listen.95-179-152-88.sslip.io
PORT=8787
```

Никогда не публикуйте этот файл или ключ в репозитории. Веб-панель хранит ключ только в памяти страницы и передаёт его в заголовке Authorization по HTTPS, не в URL. Доступ к API без ключа запрещён. Для смены ключа обновить LISTEN_KEY и перезапустить только сервис панели.

## Как работает

Сервис только читает недавние `.bin`-сегменты существующего буфера: отметка времени float64 LE, ID участника uint64 LE, размер Opus uint16 LE, пакет. Он смешивает голоса в PCM16 mono 16 kHz; браузер воспроизводит последовательные двухсекундные блоки через Web Audio. Ориентировочная задержка несколько секунд. Сервер держит только один двухсекундный блок в памяти, новые аудиофайлы не создаёт. Старые откаты через API недоступны.

Когда голосов нет или бот не подключён, возвращается тишина. Отличить эти два состояния по одному аудиобуферу нельзя. Панель не подключает бота к Discord и не управляет им. Звук воспроизводится, пока страница активна; мобильная ОС может приостановить её в фоне или при блокировке экрана.

Смена войса очищает буфер бота, но уже переданный браузеру короткий блок может доиграть. Пауза и перезапуск панели не меняют работу бота.

## Проверка

Node.js 22+, `npm ci`, `npm test`. Тесты проверяют авторизацию, CORS, отсутствие доступа к файлам, ограничение на текущий блок и смешивание настоящих синтетических Opus-пакетов без изменения исходных файлов.
